# PHISHBOOK — Setup & Run Guide

PHISHBOOK is a controlled academic web app (social-media UI + auth + admin
monitoring). It ships as a React frontend and a Laravel REST API backend
against MySQL via XAMPP.

**Academic use only.** Participants see a consent screen before they can
reach the login/registration form, telling them this is a monitored
exercise and that they should use dummy/test credentials only. Real
passwords are never stored — only hashed auth passwords and, for the
predefined dummy accounts you create yourself in the admin panel, the
plaintext test password you chose (so you can hand it back out to
participants). No participant-submitted password is ever recorded.

## 0. What's in this folder

```
phishbook/
  backend/    -> Laravel app files (migrations, models, controllers, routes)
  frontend/   -> React app (src/, public/, package.json)
  README.md   -> this file
```

The `backend/` folder is **not a full Laravel skeleton** (artisan, config/app.php,
etc. are generated by Composer, not shipped here). You'll create a fresh
Laravel 11 project and copy these files on top of it — see Step 2.

## 1. Start XAMPP and create the database

1. Open the XAMPP Control Panel and start **Apache** and **MySQL**.
2. Go to `http://localhost/phpmyadmin`.
3. Click **New**, name the database `phishbook_db`, collation `utf8mb4_general_ci`, click **Create**.

## 2. Set up the Laravel backend

```bash
# From wherever you keep projects:
composer create-project laravel/laravel phishbook-backend "11.*"
cd phishbook-backend

# Install Sanctum for API token auth
composer require laravel/sanctum

# Copy this project's backend files on top, overwriting where they overlap:
#   app/Models, app/Http/Controllers/Api, app/Http/Middleware,
#   database/migrations, database/seeders, routes/api.php, routes/web.php,
#   bootstrap/app.php, config/cors.php
# (copy the equivalent files from the backend/ folder you were given)
```

Edit `.env` (use the values from `backend/.env.example`):

```
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=phishbook_db
DB_USERNAME=root
DB_PASSWORD=

FRONTEND_URL=http://localhost:3000
SANCTUM_STATEFUL_DOMAINS=localhost:3000
```

Then:

```bash
php artisan key:generate
php artisan migrate
php artisan db:seed
php artisan serve
```

This starts the API at `http://localhost:8000`. Confirm the tables
(`users`, `login_activities`, `dummy_accounts`, `admin_activity_logs`,
`personal_access_tokens`) now appear under `phishbook_db` in phpMyAdmin.

**Default admin login** (change the password immediately after first sign-in):
- Email: `admin@phishbook.test`
- Password: `ChangeMe!2026`

**Seeded dummy accounts** (visible/manageable from Admin → Dummy Accounts):
- `test_participant1` / `TestPass!123`
- `test_participant2` / `TestPass!456`

## 3. Set up the React frontend

```bash
cd frontend
npm install
```

Create `frontend/.env`:

```
REACT_APP_API_URL=http://localhost:8000/api
```

```bash
npm start
```

This runs the user + admin site at `http://localhost:3000`.

## 4. Using the app

- **Participants:** `http://localhost:3000/` → consent screen → `/login` or `/register`.
- **Admin:** `http://localhost:3000/admin/login` → dashboard, user management,
  login activity monitoring, dummy account management.

## 5. Notes on the security/privacy design

- `login_activities.submitted_identifier` stores only the email/username
  typed into the login form — never the password.
- `password_field_completed` is a boolean; the actual password string is
  discarded the moment the login attempt is evaluated.
- `dummy_accounts.predefined_test_password_plaintext` is only ever returned
  by the `/admin/dummy-accounts` endpoints (admin + Sanctum-authenticated).
  The `users.password` column used for real authentication is always
  bcrypt-hashed, including for dummy accounts.
- All `/admin/*` API routes require a valid Sanctum token **and**
  `role === 'ADMIN'` (enforced server-side in `EnsureUserIsAdmin` middleware,
  not just hidden in the UI).
- Public auth endpoints are throttled (`throttle:20,1`) to reduce brute-force risk.
